Cada domínio pode ter:\n\n- ✅ Configurações de branding customizadas\n- ✅ Certificados SSL/TLS\n- ✅ Headers e CSS customizados\n- ✅ Webhooks de integração\n- ✅ Estatísticas de tráfego\n- ✅ Auditoria completa\n\n---\n\n## Arquitetura de Domínios\n\n### Estrutura Hierárquica\n\n```\nUsuário\n├── Workspace 1\n│   ├── Domínio 1 (exemplo.com)\n│   │   ├── Configurações\n│   │   ├── Certificado SSL\n│   │   └── Estatísticas\n│   ├── Domínio 2 (chat.exemplo.com)\n│   └── Configurações do Workspace\n├── Workspace 2\n│   ├── Domínio 1 (outro.com)\n│   └── Configurações do Workspace\n└── Workspace 3\n```\n\n### Fluxo de Dados\n\n```\n1. USUÁRIO CRIA WORKSPACE\n   ↓\n2. WORKSPACE CRIADO COM CONFIGURAÇÕES PADRÃO\n   ↓\n3. USUÁRIO ADICIONA DOMÍNIO\n   ↓\n4. GERA REGISTROS DNS\n   ↓\n5. USUÁRIO CONFIGURA DNS NO REGISTRADOR\n   ↓\n6. PLATAFORMA VERIFICA DNS\n   ↓\n7. DOMÍNIO ATIVADO\n   ↓\n8. USUÁRIO CONFIGURA BRANDING, SSL, ETC\n```\n\n---\n\n## Schema do Banco de Dados\n\n### Tabelas Principais\n\n#### 1. **workspaces**\nArmazena informações dos workspaces de cada timezone: string,\n  language: string,\n  plan: 'free' | 'starter' | 'pro' | 'enterprise',\n  status: 'active' | 'suspended' | 'deleted',\n  createdAt: Date,\n  updatedAt: Date,\n}\n```\n\n#### 2. **domains**\nArmazena domínios associados a cada workspace.\n\n```typescript\n{\n  id: number,\n  workspaceId: number,\n  domain: string, // exemplo.com\n  type: 'primary' | 'subdomain',\n  status: 'pending' | 'verified' | 'active' | 'failed' | 'expired',\n  sslStatus: 'pending' | 'valid' | 'expired' | 'error',\n  sslCertificate?: string,\n  sslExpiresAt?: Date,\n  dnsRecords: string, // JSON\n  verificationToken: string,\n  verificationMethod: 'dns' | 'cname' | 'file',\n  verifiedAt?: Date,\n  isDefault: boolean,\n  redirectUrl?: string,\n  customHeaders?: string, // JSON\n  customCss?: string,\n  customJs?: string,\n  analytics?: string, // JSON\n  createdAt: Date,\n  updatedAt: Date,\n}\n```\n\n#### 3. **workspaceSettings**\nConfigurações específicas de cada workspace.\n\n```typescript\n{\n  id: number,\n  workspaceId: number,\n  brandName?: string,\n  brandLogo?: string,\n  brandPrimaryColor: string,\n  brandSecondaryColor: string,\n  emailFrom?: string,\n  smtpHost?: string,\n  smtpPort?: number,\n  smtpUser?: string,\n  smtpPassword?: string, // Criptografado\n  requireHttps: boolean,\n  enableCors: boolean,\n  corsOrigins?: string[], //  backupFrequency: 'daily' | 'weekly' | 'monthly',\n  createdAt: Date,\n  updatedAt: Date,\n}\n```\n\n#### 4. **workspaceMembers**\nControle de acesso e permissões.\n\n```typescript\n{\n  id: number,\n invitedBy?: number,\n  acceptedAt?: Date,\n  createdAt: Date,\n  updatedAt: Date,\n}\n```\n\n#### 5. **domainAuditLog**\nRegistra todas as mudanças em domínios.\n\n```typescript\n{\n  id: number,\n domainId: number,\n  workspaceId: number,\n  certificate: string, // PEM\n  privateKey: string, // Criptografado\n  issuer?: string,\n  subject?: string,\n  issuedAt?: Date,\n  expiresAt?: Date,\n  autoRenew: boolean,\n  renewalDate?: Date,\n  status: 'active' | 'expired' | 'revoked',\n  createdAt: Date,\n  updatedAt: Date,\n}\n```\n\n#### 7. **domainStats**\nEstatísticas de tráfego e segundos\n  createdAt: Date,\n}\n```\n\n---\n\n## Router tRPC\n\n### Endpoints Disponíveis\n\n#### **Workspaces**\n\n```typescript\n// Criar workspace\ntrpc.domain.createWorkspace.mutate({\n  name: 'exemplo.com',\n  type: 'primary',\n});\n```\n\n**Resultado:**\n- Domínio criado com status `pending`\n- Token de verificação gerado\n- Registros DNS criados\n\n### Passo 2: Sistema Fornece Instruções\n\nO usuário recebe:\n```\nRegistro CNAME:\nNome: _verify.exemplo.com\nValor: verify-{token}.example.com\nTTL: 3600\n\nOu\n\nRegistro TXT:\nNome: exemplo.com\nValor: verification={token}\nTTL: 3600\n```\n\n### Passo 3: Usuário Configura DNS\n\nNo registrador de domínio (GoDaddy, Namecheap, etc), o usuário adiciona os registros.\n\n### Passo 4: Plataforma Verifica\n\n```typescript\nawait trpc.domain.verifyDomain.mutate({\n  domainId: 456,\n  verificationMethod: 'dns',\n});\n```\n\n**Verificação:**\n1. Faz query DNS para o domínio\n2. Procura pelo token\n3. Se encontrado, marca como `verified`\n4. Gera certificado SSL (Let's Encrypt)\n5. Ativa domínio\n\n### Passo 5: Domínio Ativo\n\nStatus muda para `active` e o domínio está pronto para uso.\n\n---\n\n## Checklist de Implementação\n\n### Fase 1: Schema e Banco (1 semana)\n- [ ] Criar tabelas no banco\n- [ ] Adicionar índices\n- [ ] Criar migrations\n- [ ] Testes de schema\n\n### Fase 2: Router tRPC (1 semana)\n- [ ] Implementar endpoints de workspace\n- [ ] Implementar endpoints de domínio\n- [ ] Implementar endpoints de configurações\n- [ ] Testes de API\n\n### Fase 3: Componentes React (1 semana)\n- [ ] Criar WorkspaceSettings\n- [ ] Criar DomainManager\n- [ ] Criar BrandingSettings\n- [ ] Criar SecuritySettings\n- [ ] Testes de componentes\n\n### Fase 4: Verificação de Domínio (1 semana)\n- [ ] Implementar verificação DNS\n- [ ] Integrar Let's Encrypt\n- [ ] Implementar auto-renewal de SSL\n- [ ] Testes de verificação\n\n### Fase 5: Integração (1 semana)\n- [ ] Integrar middleware de domínio\n- [ ] Testar fluxo completo\n- [ ] Deploy em staging\n- [ ] Validação\n\n---\n\n## Próximos Passos\n\n1. **Implementar Verificação DNS Real** - Usar biblioteca `dns` do Node.js\n2. **Integrar Let's Encrypt** - Para certificados SSL automáticos\n3. **Implementar Webhooks** - Para notificações de eventos\n4. **Adicionar Analytics** - Dashboard de tráfego por domínio\n5. **Implementar CDN** - Para melhor performance\n\n---\n\n**Status**: ✅ Pronto para Implementação\n**Versão**: 1.0.0\n**Autor**: Manus AI\n**Data**: 10 de Janeiro de 2026\n
